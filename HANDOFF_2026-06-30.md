### ✅ Fix 1 -- widget bug: unguarded `module.exports` (widget repo)
- `widgets-src/fortiaiAgenticAssistant/widget/widgetAssets/js/fsrPbRender.js:728`
  had bare `module.exports = api;`. That file is loaded as a plain `<script>` in
  the browser, where `module` is undefined → `ReferenceError: module is not defined`
  (cascaded into a RequireJS define error).
- **Blame:** commit `459e764` (2026-06-22, "convert render pipeline to TS") --
  the `.ts` uses `export = api`, which compiles to bare `module.exports`. **8 days
  before the rename.** The rename CLI only touched a *comment* in this file.
- **Fix:** wrapped in `if (typeof module !== 'undefined' && module.exports)`.
  The `.js` is canonical (nothing recompiles the `.ts`; `typecheck-widgets` only
  checks `view/edit.controller.js`). `.ts` left as `export = api` (type-checks,
  never emitted).
- **Gotcha worth a KB entry:** widgetAssets/*.js loaded as `<script>` must guard
  `module.exports`.

### ✅ Fix 2 -- harness bug: Monaco↔Toast-UI `define` conflict (harness repo)
- Harness `public/index.html` `loadRichTextEditors()` loads **Monaco** (AMD loader
  hijacks `window.define`) **and Toast UI Editor** (UMD bundle calls anonymous
  `define()`). Toast UI's define calls hit Monaco's hijacked loader → throws
  `Error: Can only have one anonymous define call per script file` (a `pageerror`;
  non-fatal -- widget boots, only `expect(errors).toEqual([])` specs catch it).
  Fires on first mount per worker when the widget renders a markdown/code editor
  (happy_path shows YAML → both editors load).
- **Fix:** added `injectSkipAmd(src)` in `public/index.html` that falsifies
  **`define.amd`** (NOT `define` itself) for the duration of Toast UI's load only,
  then restores. UMD wrappers gate AMD on `typeof define === 'function' &&
  define.amd`; falsifying `.amd` makes Toast UI take its global branch
  (`window.toastui.Editor`) while Monaco's define stays fully functional.
- **⚠️ Do NOT null `window.define`** -- my first attempt did
  (`Object.defineProperty(window,'define',{value:undefined})`) and broke the widget
  boot entirely (all tests timed out at the probe `waitForFunction`). `.amd`-only
  falsification is safe. dompurify/tinymce need no bracket.
- Detail memory: `harness_monaco_toastui_define_conflict`.
